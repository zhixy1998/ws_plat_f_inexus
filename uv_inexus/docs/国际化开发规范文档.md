# UV-iNexus 国际化（i18n）操作指南

> **支持语言**: 中文（zh-CN）、英文（en-US）、俄文（ru-RU）

---

## 一、翻译字典文件位置

| 文件 | 用途 | key 格式 |
|------|------|----------|
| `src/main/resources/i18n/i18n-dictionary.yaml` | API 消息码 | 8位十六进制，如 `00613001` |
| `src/main/resources/i18n/i18n-ui-texts.yaml` | UI 文本 / WebSocket 推送 | 中文原文，如 `合格` |

---

## 二、翻译是怎么生效的（先理解这个，后面才好用）

系统的翻译机制是**自动的、全量的**，理解这个就知道什么时候需要干预：

### REST API 响应 — 自动翻译整个返回数据

当你返回 `Result` / `R` 时，系统会自动做两件事：

1. **翻译 message**：根据消息码查字典翻译提示文本
2. **翻译 data 中的所有中文字符串**：系统会递归遍历 `data` 里的每个字段，只要字段值**包含中文字符**，就会去 `i18n-ui-texts.yaml` 里找对应的翻译

```
你写的代码：                          用户看到的（英文环境下）：
Result.ok(data)                       Result.ok(translatedData)

data = {                              translatedData = {
  "name": "紫外分光光度计",     →        "name": "UV Spectrophotometer",
  "status": "检测完成",         →        "status": "Detection completed",
  "id": "ABC123",               →        "id": "ABC123",       ← 不含中文，不翻译
  "serialNumber": "SN-001"      →        "serialNumber": "SN-001"  ← 不含中文，不翻译
}                                      }
```

**关键点**：系统**不区分字段的业务含义**，翻译的唯一判断标准是——**这个字符串里有没有中文字符**。有中文就去字典找翻译，没有就原样返回。

### WebSocket 推送 — 同理

通过 `OutputTranslator` 推送的 JSON 数据，也是自动遍历所有字段，含中文的就翻译。

### 所以为什么需要 @NoI18n？

大部分时候你不需要关心，系统自动翻译就对了。但有一种情况需要干预：

**当你的字段值恰好包含中文字符，但它不是给人看的文本，不应该被翻译。**

比如：
```java
public class TaskDTO {
    private String taskName;              // "吸光度检测" → 含中文 → 应该翻译 ✅

    @NoI18n
    private String filePath;              // "C:/数据/报告/报告1.pdf" → 含中文但不该翻译
                                           // 如果不标 @NoI18n，路径中的"数据""报告"会被错误翻译

    @NoI18n
    private String formula;               // "吸光度_修正值" → 含中文但是公式标识，不该翻译
}
```

**简单判断**：如果这个字段的中文被翻译成英文后，**程序功能会受影响**（比如路径、公式、编码），就加 `@NoI18n`。如果是给用户看的显示文本，不用管，自动翻译。

## 三、新接口怎么加国际化

### 场景一：REST API 返回消息（最常用）

**第 1 步**：在 `i18n-dictionary.yaml` 中添加消息码

```yaml
messages:
  # ========== 你的模块名 (模块码+子模块码) ==========
  '00705001':
    zh-CN: '导出文件名不能为空'
    en-US: 'Export filename cannot be empty'
    ru-RU: 'Имя файла экспорта не может быть пустым'
```

**第 2 步**：在代码中使用消息码

```java
// 普通用法
return Result.fail("00705001");
return R.fail("00705001");

// 带动态参数（用 {0}, {1} 占位）
return Result.fail("00705002", "波长", "190nm");
```

**也可以直接写中文**，只要在 `i18n-dictionary.yaml` 或 `i18n-ui-texts.yaml` 中以中文原文为 key 配置了翻译，系统同样会自动翻译：
```java
// 这样也能翻译，只要 yaml 里配了 '导出文件名不能为空' 的翻译
return Result.fail("导出文件名不能为空");
```

**但推荐用消息码**，原因：
- 消息码唯一、好追踪、方便搜索所有引用
- 直接写中文如果以后改了文案，翻译容易漏改
- 消息码支持占位符 `{0}`, `{1}`，中文原文做不到

---

### 场景二：WebSocket 推送中文文本

**第 1 步**：在 `i18n-ui-texts.yaml` 中以中文原文为 key 添加翻译

```yaml
messages:
  '检测完成':
    zh-CN: '检测完成'
    en-US: 'Detection completed'
    ru-RU: 'Обнаружение завершено'
```

**第 2 步**：代码中正常写中文，系统会自动翻译

```java
JSONObject data = new JSONObject();
data.put("result", "检测完成");   // 自动翻译
```

> key 必须和代码中的中文文本**完全一致**，包括空格和标点。

---

### 场景三：手动翻译文本

```java
@Autowired
private I18nMessageUtil i18nMessageUtil;

// 通过消息码（自动获取当前语言）
String msg = i18nMessageUtil.getMessage("00613001");

// 指定语言
String msgEn = i18nMessageUtil.getMessage("00613001", "en-US");

// 中文原文翻译（找不到则返回默认值）
String text = i18nMessageUtil.getMessageWithDefault("合格", "合格");
```

---

### 场景四：Excel 导出翻译

```java
@Autowired
private I18nExcelHelper i18nExcelHelper;

// 翻译单个文本
String header = i18nExcelHelper.t("检测结果");

// 翻译多个表头
String[] headers = i18nExcelHelper.t(new String[]{"样品名", "波长", "吸光度"});
```

---

### 场景五：WebSocket 推送消息

```java
@Autowired
private WebSocketSendUtil webSocketSendUtil;

// 简单推送（消息码）
webSocketSendUtil.sendI18nMessage(userId, "00613001");

// 自定义推送
webSocketSendUtil.sendI18nMessageCustom(userId, 1, "00610002", "00613001");
```

## 四、@NoI18n 使用说明

> 前面第二节已经解释了翻译机制。这里总结 `@NoI18n` 的用法。

### 什么时候加 @NoI18n？

**只要字段值包含中文，系统就会尝试翻译。** 如果这个字段不应该翻译，就要加 `@NoI18n`。

典型需要加的场景：

| 场景 | 字段值示例 | 为什么不能翻译 |
|------|-----------|---------------|
| 文件路径 | `"C:/数据/报告/report.pdf"` | 翻译后路径失效，文件找不到 |
| 公式/标识 | `"吸光度_修正值"` | 程序依赖这个字符串做匹配 |
| 编码/配置项 | `"方法A-标准检测"` | 代码中按这个值做逻辑判断 |
| 数据库字段名 | `"样品名称"` | 用于 SQL 或反射，翻译后报错 |

### 什么时候不用加？

- 字段值是纯英文/数字（如 `"SN-001"`, `"ABC123"`）—— 不含中文，系统自动跳过
- 字段值是给用户看的显示文本（如 `"检测完成"`, `"合格"`）—— 正是需要翻译的

### 怎么加？

```java
import com.persee.workstation.uv_inexus.i18n.NoI18n;

public class TaskDTO {
    private String taskName;              // 用户看的，不用加，自动翻译

    @NoI18n
    private String filePath;              // 文件路径，含中文但不能翻译

    @NoI18n
    private String formula;               // 公式标识，含中文但不能翻译

    private String taskId;                // 不用加，纯英文/数字，系统自动跳过
}
```

## 六、YAML 文件格式要求

```yaml
messages:
  # ========== 注释：模块名 (模块码+子模块码) ==========

  '00705001':
    zh-CN: '导出文件名不能为空'
    en-US: 'Export filename cannot be empty'
    ru-RU: 'Имя файла экспорта не может быть пустым'

  '00705002':
    zh-CN: '波长 {0} 超出范围 {1}'
    en-US: 'Wavelength {0} exceeds range {1}'
    ru-RU: 'Длина волны {0} превышает диапазон {1}'
```

- UTF-8 编码
- 翻译文本用**单引号**包裹
- 三语必须同时填写
- 按模块加注释分隔
- 不要修改已有的 key

---

## 七、异步线程中翻译

```java
LocaleContext.executeWithLocale("en-US", () -> {
    String msg = i18nMessageUtil.getMessage("00613001");
    // 这里的翻译都会用 en-US
});
```

## 八、快速检查清单

新接口完成后检查：

- [ ] API 消息是否在 `i18n-dictionary.yaml` 注册了消息码？
- [ ] 代码中用的是 `Result.fail("码")` 而非中文字符串？
- [ ] 三语翻译是否全部填写？
- [ ] WebSocket 推送的中文是否在 `i18n-ui-texts.yaml` 注册
- [ ] Excel 表头是否用了 `I18nExcelHelper.t()`？
- [ ] 不翻译的字段是否标了 `@NoI18n`？
